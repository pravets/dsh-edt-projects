# Changelog

Формат — [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/),
версии — [SemVer](https://semver.org/lang/ru/).

С 2026-11-06 проект версионируется как **0.x**: это бета, поэтому совместимость
ключей `.dsh-1c.json`, имён инструментов и `cordis.patch.yml` между версиями не
гарантируется. История ниже пересчитана по одной шкале (1.N.M → 0.N.M), прежних
публикаций в npm не было. Версия 1.0.0 будет означать зафиксированный API.

## [0.11.0] - 2026-11-09

### Добавлено

- MCP-сервер `v8std` — публичная read-only база стандартов 1С и диагностик
  (`https://ai.v8std.ru/mcp`). Сервер ленивый: подключается по `edt_pin("v8std")`,
  когда EDT (`get_project_errors`) или BSL LS (`analyze_file`) выдал код ошибки
  либо задан вопрос про стандарт.
- Правила для модели: разрешать коды через `v8std_explain_diagnostics`, читать
  правило через `v8std_get_page`, искать тему через `v8std_search`, разбирать один
  метод BSL/фрагмент SDBL через `v8std_explain_snippet`; ссылки на стандарт не
  выдумывать, а результат поиска не выдавать за подтверждённое нарушение.
- Свой инстанс v8std: `servers.v8std.url` / `servers.v8std.headers` в файлах
  настроек или `V8STD_MCP_URL` / `V8STD_MCP_TOKEN`. Значение по умолчанию живёт
  только в `cordis.patch.yml` (в `DEFAULTS` его нет, чтобы `upgrade` не перекрыл
  переменную окружения).
- Smoke дополнительно проверяет, что строка `v8std` попала в композицию профиля;
  тесты правил и схемы — 116 проверок.

## [0.10.0] - 2026-11-07

### Добавлено

- Плагин включается **только в выбранных проектах**. Решение принимается по
  исходному каталогу сессии: `enabled: true` в настройках, наличие разбираемого
  `.dsh-1c.json` проекта или путь в `projects` файла `$DSH_HOME/dsh-1c.json`.
  `enabled: false` сильнее файла проекта и списка. В выключенном проекте в контексте
  не остаётся ни правил 1С, ни MCP-инструментов, ни навыков — только `edt_config`.
- Включение на лету: `edt_config action=init` создаёт `.dsh-1c.json`, и проект
  активируется со следующего шага сессии без перезапуска DSH (проверка идёт в
  `agent/created` и в `agent/pre-step`).
- Схема настроек v2: ключи `enabled` (boolean) и `projects` (массив путей).
  `edt_config upgrade` добавляет `projects`, но не `enabled`, чтобы не выключить
  уже работающий проект.

### Изменено

- **Серверы монтируются в скоупе сессии, а не один раз на процесс.** EDT
  подключается при создании сессии включённого проекта, заленивые серверы — по
  `edt_pin`. Инструменты одного проекта больше не протекают в другой, а число
  клиентов EDT растёт на сессию (для HTTP это отдельное подключение, не workspace).
- **Инструменты переименованы** в собственное пространство `edt_`: `mcp_config` →
  `edt_config`, `mcp_servers` → `edt_servers`, `mcp_pin` → `edt_pin`,
  `mcp_unpin` → `edt_unpin`, `mcp_reload` → `edt_reload`. Старые имена были
  конфликтными (`mcp_config` пересекался с настройками MCP-панели) и не описывали
  весь плагин: `edt_config` управляет включением проекта, вики, тестами, серверами и
  навыками. Псевдонимов нет — это breaking-изменение для проектных навыков и
  AGENTS.md, которые ссылались на старые имена.
- `servers.*.shared` больше не влияет на монтаж: ключ принимается как устаревший
  no-op, сервер всегда живёт в скоупе сессии.
- Правила, навыки и вики считаются только для включённого проекта; авто-включение
  навыка Sonar по `servers.sonarqube` тоже действует лишь внутри него.
- Skill-провайдер инвалидирует каталог при изменении файлов настроек и после
  `edt_config`/`edt_reload`, поэтому включение проекта не ждёт перезапуска.
- Smoke проверяет обе стороны: из каталога без `.dsh-1c.json` заглушка MCP не
  получает `initialize`, из каталога с файлом — получает.
- Тесты: 112 проверок (добавлены `enable.test.mjs`, включение навыков по проекту,
  факт наличия файла проекта).

## [0.9.0] - 2026-11-06

### Добавлено

- Токен GitHub для API: `DSH_1C_BSL_LS_GITHUB_TOKEN` (запасные `GITHUB_TOKEN`,
  `GH_TOKEN`). Уходит только в запросы к `api.github.com` и поднимает лимит с 60
  до 5000 запросов в час; в `.dsh-1c.json` не хранится, чтобы секрет не попал в git.
- Загрузка со страниц релизов (`resolveReleaseViaHtml`): тег последнего релиза
  берётся из редиректа `releases/latest`, ссылка на `*-exec.jar` и `sha256` — со
  страницы `releases/expanded_assets/<тег>`. Без токена это основной источник,
  поэтому лимит API больше не условие инициализации.
- `predictAsset`: предсказуемый адрес ассета
  `releases/download/<тег>/bsl-language-server-<версия>-exec.jar` как последний
  сетевой резерв — без `sha256` и с предупреждением в логе.
- Кэш как запасной путь: если релиз недоступен, а в кэше есть jar другой версии,
  он используется с предупреждением вместо падения `mcp_pin`.
- `warn` в зависимостях загрузчика: предупреждения идут в лог DSH через
  `ctx.logger.warn`, а не только `info`.
- Публикация в npm: пакет `dsh-edt-projects` ставится как
  `plugin_manager { action: "install_bundle", target: "dsh-edt-projects" }`.
  В тарболл добавлены `README.md` и `LICENSE`, в манифесте — `license`,
  `repository`, `homepage`, `bugs`, `keywords`, `publishConfig.access: public`.
- CI: `release.yml` публикует версию из тега в npm через trusted publisher
  (OIDC, без токенов и секретов; идемпотентно — уже опубликованную версию
  пропускает).

### Исправлено

- Ответ GitHub API с лимитом запросов распознаётся по `x-ratelimit-*` и тексту
  ответа и превращается в `RateLimitError` с временем сброса и перечнем выходов,
  а не в голый `HTTP 403`.
- `bslAvailable` учитывает кэш: при `DSH_1C_BSL_LS_DOWNLOAD=0` сервер остаётся
  доступным, если jar уже скачан.
- Несовпадение `sha256` больше не «обходится» повтором с другого источника:
  `IntegrityError` поднимается сразу, файл в кэш не попадает.

### Изменено

- Переверсионирование 1.9.0 → 0.9.0: проект в статусе беты, SemVer 0.x честнее
  заявляет нестабильность. Нумерация истории пересчитана 1.N.M → 0.N.M; тег
  `v1.0.0` снят, текущий тег — `v0.9.0`.
- Пакет и репозиторий переименованы: `dsh-edt-plugin` → `dsh-edt-projects`,
  пакет `@local/dsh-edt-mcp` → `dsh-edt-projects`. Репозиторий стал публичным.
- Каталог бандла `edt-mcp/` → `plugin/` (workspace, скрипты, workflow-ы и пути
  в документации); имена навыков `edt-mcp-project-*` и провайдер
  `edt-mcp-bundle-skills` не менялись — это отдельный неймспейс.
- Порт EDT по умолчанию — `8765` вместо `8767`, как у самого EDT-MCP; в
  `cordis.patch.yml`, `lib/schema.mjs`, smoke-заглушке и документации. Если порт
  занят, его по-прежнему переопределяет `EDT_MCP_URL`.
- `tools/check-edt-mcp.mjs` разбирает адрес из `!!js`-выражения в патче (раньше
  молча брал константу), больше не содержит личного пути к npx-кэшу и требует
  `DSH_MCP_SDK_DIR` либо `npm install`.
- Валидатор бандла проверяет готовность к публикации (`private`, `license`,
  `README`/`LICENSE`) и совпадение порта EDT в патче и `DEFAULTS`.
- Тесты: 98 проверок (`tools/bsl.test.mjs` — 23).

## [0.5.0] - 2026-11-03

### Добавлено

- Слоистые настройки: база из `cordis.patch.yml` ← `$DSH_HOME/dsh-1c.json` ←
  `<cwd>/.dsh-1c.json`. Файлы перечитываются на каждый `mcp_pin`, `mcp_reload` и
  рендер промпта, поэтому адреса, заголовки и корни меняются без перезапуска DSH.
- Инструмент `mcp_reload(server?)`: перечитывает настройки и перезапускает
  подключённые серверы, у которых изменились `url`, `headers`, `command`, `args`,
  `cwd` или `root`.
- Наблюдение за файлами настроек (`fs.watch`): при изменении в лог пишется
  подсказка вызвать `mcp_reload`.
- Вики проекта: `wiki.paths` и `wiki.entry` дают блок в промпте, а `ctx.tools.guard`
  отклоняет `edit`, `write`, `str_replace_editor`, `apply_patch` по путям вики —
  документация доступна только для чтения.
- Серверы без `shared: true` монтируются в скоуп агента, поэтому параллельные
  агенты в разных git-worktree держат каждый свой `bsl` со своим корнем; `edt`
  помечен `shared: true` (один workspace на процесс).
- Корень BSL LS по умолчанию берётся из `servers.bsl.root` настроек проекта.
- Тесты: `tools/config.test.mjs` (7) и `tools/wiki.test.mjs` (9), всего 42 проверки.

### Изменено

- `bslSettings` больше не фиксируется в замыкании `apply`: настройки BSL LS
  пересобираются из окружения и файлов на каждое монтирование.
- Валидатор бандла видит `wiki` в конфиге хаба и `shared` у серверов.

## [0.4.0] - 2026-11-03

### Добавлено

- Правило «Правки конфигурации — только через EDT»: модели предписано менять
  исходники 1С инструментами `edt__*` (`write_module_source`, `create_metadata`,
  `modify_metadata`, `rename_metadata_object`, `delete_metadata`, `dcs`,
  `apply_quick_fix`), а не через `edit`/`write`/`pwsh`.
- Процедура эскалации: если подходящего инструмента EDT нет — остановиться,
  сообщить пользователю, что пробовал, и предложить issue в
  https://github.com/DitriXNew/EDT-MCP/issues с версией сервера и примером задачи.
- Прямая правка файла разрешена только по явному согласию пользователя, с
  предупреждением об устаревании модели EDT и предложением `revalidate_objects`
  или `resync_to_disk`.
- `mcp_pin("bsl", root: "<каталог конфигурации>")` задаёт корень рабочего
  пространства в рантайме; при смене корня сервер перезапускается.
- `mcp_pin(..., mode: "stdio" | "hybrid")` — выбор режима на конкретный вызов.
- `mcp_servers` показывает у управляемого сервера корень и адрес эндпоинта.

### Изменено

- Из блока EDT убрана формулировка «правь инструментами EDT, а не только текстовым
  редактором»: слово «только» фактически разрешало смешанный режим.
- Тесты: 23 проверки, включая наличие правила при настроенном EDT, его отсутствие
  без EDT и работу правила при временно недоступном сервере.

### Исправлено

- Несуществующий каталог корня BSL LS теперь даёт ошибку сразу
  (`каталог рабочего пространства не найден: …`), а не ожидание порта в 180 с:
  `spawn` с несуществующим `cwd` падал с `ENOENT`, и это выглядело как таймаут.
- Синхронная ошибка `spawn` (нет прав на создание процесса) и ранний выход
  процесса тоже прерывают ожидание и попадают в текст ошибки.

## [0.3.0] - 2026-11-02

### Добавлено

- BSL LS запускается в гибридном режиме `lsp --mcp`: LSP-инициализация объявляет
  рабочее пространство (`DSH_1C_BSL_LS_ROOT`), MCP открывается по Streamable HTTP
  на том же процессе. Без этого все инструменты падали с
  `File is not part of any registered workspace`: `dsh-mcp-client` не объявляет
  capability `roots`, а BSL LS берёт корни только оттуда.
- Переменные `DSH_1C_BSL_LS_ROOT`, `DSH_1C_BSL_LS_PORT`, `DSH_1C_BSL_LS_MODE`
  (`hybrid` по умолчанию, `stdio` — старый режим без корней).
- Хаб гасит процесс BSL LS при `mcp_unpin` и при выгрузке плагина.

### Изменено

- `resolveBsl` остался для режима `stdio`; по умолчанию используется
  `startBslSupervisor`.
- Проверено на живом сервере: после `mcp_pin("bsl")` `analyze_file` вернул 57
  диагностик по модулю `Catalogs/Организации/ManagerModule.bsl`.

## [0.2.0] - 2026-11-02

### Добавлено

- Автозагрузка BSL Language Server: если `DSH_1C_BSL_LS_JAR` не задан, при первом
  `mcp_pin("bsl")` хаб скачивает fat-jar `bsl-language-server-<версия>-exec.jar`
  из релизов 1c-syntax/bsl-language-server, сверяет `sha256` из GitHub API,
  пишет через `.part` и кэширует.
- Переменные `DSH_1C_BSL_LS_URL`, `DSH_1C_BSL_LS_VERSION`, `DSH_1C_BSL_LS_CACHE`,
  `DSH_1C_BSL_LS_DOWNLOAD`, `DSH_1C_BSL_LS_JAVA`, `DSH_1C_BSL_LS_CWD`,
  `DSH_1C_BSL_MCP_URL` с префиксом `DSH_1C_`, чтобы не пересекаться с окружением
  машины; старые имена `BSL_LS_*` принимаются как запасные.
- Флаг `provision: true` у сервера: параметры запуска добираются на `mcp_pin`.
- `tools/bsl.test.mjs` — 9 тестов: приоритет настроек, выбор ассета, кэш,
  скачивание с проверкой sha256, отказ при запрете скачивания.

### Изменено

- `mcp_servers` показывает BSL LS как `lazy` (а не `unavailable`): сервер можно
  подготовить самому, скачав jar.
- Правила для модели предупреждают, что первый `mcp_pin("bsl")` может скачивать
  ~130 МБ.

## [0.1.0] - 2026-11-02

### Добавлено

- Хаб `mcp-hub` (`edt-mcp/lib/index.js`): бандл сам монтирует серверы, поэтому
  набор инструментов можно менять без перезапуска.
- Подключение по требованию: флаг `lazy: true` у сервера и мета-инструменты
  `mcp_servers` (состояние), `mcp_pin` (смонтировать), `mcp_unpin` (снять).
  Инструменты, подключённые посреди сессии, попадают в следующий запрос модели,
  DSH фиксирует это блоком `tool-addition`.
- Флаг `unavailable: !!js '…'`: сервер виден в правилах, но `mcp_pin` объясняет,
  какой переменной окружения не хватает.
- Правила для модели собираются из состояния серверов: пока сервер не смонтирован
  или не настроен, инструкций по его инструментам в промпте нет — только про `mcp_pin`.
- BSL Language Server по stdio (`BSL_LS_JAR`, `BSL_LS_JAVA`, `BSL_LS_CWD`) или по
  Streamable HTTP (`BSL_MCP_URL`), система задач (`TASKS_MCP_URL`, `TASKS_MCP_TOKEN`),
  EDT (`EDT_MCP_URL`, `EDT_MCP_TOKEN`).
- `tools/stub-mcp-server.mjs` — минимальный MCP-сервер (Streamable HTTP, JSON-RPC
  без SSE) с инструментом `ping`, который отвечает `pong`.
- `tools/smoke-bundle.mjs` — полный прогон бандла: одноразовый `DSH_HOME`,
  установка из `dist/*.tgz` через `dsh plugin add`, проверка композиции профиля,
  живая MCP-сессия с заглушкой (`initialize`, `tools/list`).
- `tools/rules.test.mjs` и `npm test` — правила, `normalizeServers`, `mountConfig`.
- Workflow `smoke.yml` — запуск smoke по расписанию, вручную и на push/PR, которые
  трогают бандл.

### Изменено

- Бандл стал код-бандлом: появились `main`/`exports["."]` и `lib/`.
- `config.servers` в `cordis.patch.yml` заменил строки `@deepseek-ai/dsh-mcp-client`;
  лишние для выбранного транспорта поля отбрасываются при монтировании.
- EDT подключается сразу и синхронно (его инструменты есть в первом запросе),
  BSL LS и система задач — по умолчанию ленивые.
- Бандл зависит от `@deepseek-ai/dsh-mcp-client@0.2.1-rc.5`: версия должна
  совпадать с версией DSH.
- `validate-bundle.mjs` понимает `!!js`-выражения, проверяет точку входа и что
  в хабе есть сервер, подключаемый сразу; `smoke-bundle.mjs` проверяет строку хаба
  и живое подключение EDT.
